# H0 spike: live PTY handover (P6 feasibility)

Status: SPIKE DONE (docs + throwaway code under `spike/handover/`, no product code touched). Parent: `docs/plans/session-host-architecture.md` sections 7, 7.1, 7.2.
Run: `spike/handover/run.sh` (Linux, private target dir) and `cargo run --release --bin vtrt` (VT round trip). Linux 7.0 (this box) and macOS (Darwin 27, bigmac over ssh, built under `~/h0spike`).

Question: can a live pane move to ANOTHER process without killing or resetting the shell?

## Verdict table

| # | Claim | Verdict | Evidence |

| 1c | No output lost or duplicated (counter loop `CNT 0..N`, 5 ms period) | **VERIFIED with two conditions** | Linux: 349 consecutive counter lines across the handover, 0 gaps/dups, even with the owner EXITING and nobody reading for 600 ms (kernel PTY buffer held the output; shell never blocked/lost). | 2a | Adopter can track the child without being its parent | **VERIFIED (liveness), REFUTED (exit status)** | `waitpid(pid)` and `waitid(P_PIDFD)` on a non-child return `ECHILD`: exit code/signal are NOT obtainable by the adopter (the real parent or init reaps it). ## Recommendation

Keep **A (side-by-side SCM_RIGHTS)** as the mechanism: it is proven on Linux and macOS, rollback stays trivial, and every blocker found is solvable inside bilterm. Adopt these refinements to section 7.2:

1. Old host MUST stop its blocked PTY reader thread before sending fds (verdict 1d). This is the single hard prerequisite and it is a P1 change (pollable reader with a wake fd).
2. Old host keeps ALL its fd copies open until the new host has acked (verdict 1e); required on macOS, harmless on Linux.
3. Do not promise child exit status after handover (2a). Options: (a) accept "exited, status unknown"; (b) keep the old host process alive as a thin "reaper/parent" per session (it must not exit then, which weakens "old binary goes away"); (c) use fallback B for hosts where status matters. Recommend (a) for v1, documented.
4. Use B only for the supervisor itself (it owns no PTYs) and as a fallback where an AF_UNIX handover socket is impossible; it is a good B-style option for the SINGLE-process in-place upgrade of one host if rollback is waived, because it preserves parenthood.
5. State export = history rows + `state_formatted` + explicit extras (3c), not plain `GridSnapshot`. Handover quality is "visually identical main screen; apps self-heal alt-screen/regions after the SIGWINCH nudge".

## Task breakdown

**H1 (P1 prerequisites; no handover yet)**
- H1.1 `PtySession` ownership: `into_raw_parts()`/`from_raw_parts(fd, pid, size)` and `release()` that suppresses the kill/wait in `Drop` (`src/pty/mod.rs:398`). Unix only; Windows returns `Unsupported`.
- H1.2 Pollable reader: replace blocking `reader.read` with `poll(master, wake_fd)`; `quiesce()` returns only after the thread has parked and its last chunk was delivered to VT; `resume()`. Test: `owner --keep` hazard no longer reproduces (counter test, 0 gaps).
- H1.3 fd registry: PTY masters, listeners, locks tracked; confirm CLOEXEC everywhere (portable-pty master is CLOEXEC).
- H1.4 Pid supervision abstraction (`ChildWatch`): pidfd on Linux, `kqueue EVFILT_PROC` or master-EIO on macOS, plus "status unknown" exit report path for non-parent.
- H1.5 Seed `current_size` dedup from adopted size.

**H2 (state export and handover)**
- H2.1 `HostSnapshot` VT section: history rows + `state_formatted` + alt-screen handling (main then `?1049h` + alt) + pending-sequence tail + graphics placements + Kitty keyboard stack + cwd; round-trip property tests built from `spike/handover/src/vtrt.rs` cases (alt, split escape, regions, charset, graphics).
- H2.2 `handover::fdpass` (`sendmsg`/`recvmsg` SCM_RIGHTS, peer-cred check, `0700` socket dir via `secure_fs`), unit-tested with the counter loop (port `spike/handover` to an `#[ignore]` integration test, Linux and macOS).
- H2.3 Protocol steps 1-6 of section 7.2 with rollback fault injection; add the macOS rule "no close before ACK" as a test.
- H2.4 Post-handover SIGWINCH nudge + resize dedup bypass; assert `trap WINCH` fires once.
- H2.5 Windows: snapshot-only fallback (separate task; ConPTY unverified here).

## Risks

- Pending-sequence tail and alt screen are the two correctness gaps most likely to be visible to users (vim/htop mid-redraw).
- Exit status after handover is lost for a non-parent adopter (documented decision needed).
- macOS discard-on-close is a platform subtlety that fails silently (one line lost); needs a CI-able test on the Mac runner.
- Not tested: tmux-backed panes, graphics payload size, many-fd (1000 panes) fd limits, `kqueue EVFILT_PROC`, Windows.
